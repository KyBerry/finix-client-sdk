# FinixClient

<p className="lead">The entry point. Holds your environment and application id, and puts the hosted form on the page.</p>

```ts
import { FinixClient } from "@kyberry/finix-client-sdk";

const client = new FinixClient({ environment: "sandbox", applicationId: "AP_..." });
```

In React, prefer `useFinixClient(config)` from the React entry; it does the same and keeps the client stable across renders.

## `mount(element, options?, asyncOptions?)`

```ts
const form = await client.mount("payment-form", { paymentMethods: ["card"] });
```

- `element`: your container, as an element or its id. The SDK adds its own child `div` inside it (`data-finix-payment-form="v2"`) and hands that to Finix, so anything else inside your container is left alone.
- `options`: everything Finix accepts for its PaymentForm, plus this SDK's callbacks. See [Options](#options).
- `asyncOptions`: `{ timeoutMs?, signal? }`.

Resolves with a [`PaymentFormInstance`](/docs/reference/payment-form) once Finix says the form is ready. Rejects with:

- `payment_form_unavailable` if Finix did not return a form,
- `timeout` if the ready timeout passes,
- `aborted` if your signal fires,
- `invalid_configuration` if the container does not exist or an option is wrong.

If mounting fails, the SDK removes anything it created and calls `onError` once.

## Options

All of Finix's documented options are passed through as-is: `paymentMethods`, `showAddress`, `hideFields`, `requiredFields`, `defaultValues`, `labels`, `placeholders`, `theme`, `styles`, `fonts`, and so on. Card values are rejected in `defaultValues`.
