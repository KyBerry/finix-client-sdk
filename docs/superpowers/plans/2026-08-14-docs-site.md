# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `apps/docs`, a documentation site for `@kyberry/finix-client-sdk` with guides, a hand-written API reference, and live hosted-form examples.

**Architecture:** A self-contained Next 15 app-router app on Tailwind v4 with shadcn/ui components generated on the React Aria base (`style: aria-vega`, `iconLibrary: phosphor`). Doc pages are file-based MDX routes under `app/docs/**/page.mdx`, highlighted at build time by `rehype-pretty-code`. Live examples are client components whose own source is read from disk by a server component so the Code tab never drifts from what runs.

**Tech Stack:** Next 15.5.23, React 19, Tailwind 4, shadcn CLI 4 (`--base aria --preset vega`), `react-aria-components`, `@phosphor-icons/react`, `@next/mdx` 15.5.23, `remark-gfm`, `rehype-slug`, `rehype-pretty-code`, `shiki`, `next-themes`, Vitest + jsdom + Testing Library, `@kyberry/finix-client-sdk` (`workspace:*`).

Spec: `docs/superpowers/specs/2026-08-14-docs-site-design.md`.

## Global Constraints

- App lives at `apps/docs`, package name `@kyberry/finix-client-sdk-docs`, dev port **3001**. Do not modify `apps/playground` or `packages/ui`.
- Tailwind **v4** only; do not depend on `@kyberry/ui`.
- Components come from `shadcn` with `--base aria`; icons only from `@phosphor-icons/react`, regular weight, 16px (`size={16}`), functional use only. Remove `lucide-react` if the CLI installs it.
- Typography: system sans stack for prose and UI; mono only for code and literal values. Define `--font-sans` and `--font-mono` explicitly in `globals.css` (an undefined `var()` invalidates the whole `font-family` declaration).
- Prohibited visual gestures: comment-style `//` headers, mono uppercase eyebrows or badges, `01`-style indexing, gradients, decorative icon rows, card grids for prose, hero artwork.
- One accent for links/focus/current-nav: `--accent-link` (light `oklch(0.52 0.16 255)`, dark `oklch(0.72 0.14 255)`).
- Every doc page exports `metadata = { title, description }`.
- Live examples read `process.env.NEXT_PUBLIC_FINIX_APPLICATION_ID`; when unset they render a notice, never throw.
- Commits: Kyle's standing instruction is "do not commit unless asked." Keep the commit steps below only if he has explicitly authorized commits for this work; otherwise skip them and leave changes in the working tree. If committing, add only `apps/docs` and `docs/superpowers` paths — never the pre-existing uncommitted files elsewhere in the tree.
- Verify in the real browser before claiming done (light + dark, desktop + mobile).

```ts
export interface NavItem {
  title: string;
  href: string;

export const NAVIGATION: NavSection[] = [

      { title: "React", href: "/docs/reference/react" },
      { title: "Auth", href: "/docs/reference/auth" },
      { title: "Error codes", href: "/docs/reference/errors" },
      { title: "Types & constants", href: "/docs/reference/types" },
    ],
  },
  {
    title: "Examples",
    items: [
      { title: "Basic card form", href: "/docs/examples/basic-card" },
      { title: "Themed appearance", href: "/docs/examples/themed-appearance" },
      { title: "React headless", href: "/docs/examples/react-headless" },
    ],
  },
];

export function flattenNavigation(): NavItem[] {
  return NAVIGATION.flatMap((section) => section.items);
}

export function findNavNeighbors(pathname: string): { previous?: NavItem; next?: NavItem } {
  const items = flattenNavigation();
  const index = items.findIndex((item) => item.href === pathname);
  if (index === -1) {
    return {};
  }
  return { previous: items[index - 1], next: items[index + 1] };
}
```

```ts
import { readFileSync } from "node:fs";
import path from "node:path";

export function getSdkVersion(): string {
  const manifestPath = path.resolve(process.cwd(), "..", "..", "packages", "sdk", "package.json");
  const manifest = JSON.parse(readFileSync(manifestPath, "utf8")) as { version?: unknown };
  return typeof manifest.version === "string" ? manifest.version : "0.0.0";
}
```

```tsx
import { useTheme } from "next-themes";

import { Button } from "@/components/ui/button";

export function ThemeToggle() {
  const { resolvedTheme, setTheme } = useTheme();
  const [mounted, setMounted] = useState(false);
  useEffect(() => setMounted(true), []);
  const isDark = mounted && resolvedTheme === "dark";

  return (
    <Button
      variant="ghost"

      onPress={() => setTheme(isDark ? "light" : "dark")}

}
```

```tsx
      (entries) => {

        if (visible.length > 0) {

        }
      },
      { rootMargin: "-64px 0px -70% 0px", threshold: [0, 1] },
    );
    nodes.forEach((node) => observer.observe(node));
    return () => observer.disconnect();
  }, []);
```

````mdx
# Tokenization flow

The SDK's design goal is that primary account numbers never exist in your page.

```text
Your page (your markup, this SDK, your CSP)
└── One iframe from https://js.finix.com
    ├── The sensitive inputs, rendered by Finix
    └── Tokenization POST directly to finix.{sandbox,live}-payments-api.com

<Steps>
  <Step title="Mount">
    `FinixClient.mount()` loads Finix.js, appends an SDK-owned mount node inside your host element, and asks Finix to render its iframe there. It resolves once Finix reports the form initialized.
  </Step>
  <Step title="Validate">
    Finix calls `onUpdate(state, binInformation, hasErrors)` as the user types. The SDK sanitizes the state and exposes `hasErrors` so you can gate your submit control. Nothing sensitive is in `state`.
  </Step>
  <Step title="Submit">
    `form.submit()` asks Finix to tokenize inside the iframe. The Promise resolves with a validated `FinixTokenResponse`; the token is `response.data.id`.
  </Step>
  <Step title="Claim on your server">
    Send the token to your backend immediately and create a Payment Instrument with an authenticated server-side request. Treat the token as short-lived and honor `expires_at` when present.
  </Step>
</Steps>
````

````mdx
## Adapt your design system

`defineFinixHostedAppearanceAdapter()` is consumer-theme-first: your app keeps ownership of its tokens and resolves them to literal values Finix can receive.

import { defineFinixHostedAppearanceAdapter } from "@kyberry/finix-client-sdk";

  fieldBackground: string;
  fieldText: string;
  focusRing: string;
}

  styles: {
    default: {
      input: {
        default: { backgroundColor: theme.fieldBackground, color: theme.fieldText },
        focused: { boxShadow: `0 0 0 3px ${theme.focusRing}` },

    },
  },

  fieldBackground: "#ffffff",
  fieldText: "#0f172a",
````

````mdx
# Errors, timeouts & abort

Wrapper failures are `FinixSdkError` instances with a stable `code`, a message, and optional `details` and `cause`.

```ts
import { FinixSdkError } from "@kyberry/finix-client-sdk";

try {
  await form.submit();
} catch (error) {
  if (error instanceof FinixSdkError && error.code === "tokenization_failed") {
    // show error.message; error.details holds Finix's payload
  }
}
```

## Where errors surface

- `mount()` and `submit()` reject with `FinixSdkError` — always wrap them in `try`/`catch` (or `.catch`).
- `onSubmit` receives normalized tokenization or response errors when Finix renders the button.
- `onError` is reserved for wrapper lifecycle, validation, and callback failures. It does not replace `try`/`catch`.
- In React, `error` holds mount/lifecycle failures and `submissionError` the last tokenization failure.

## Timeouts

Both async operations accept `{ timeoutMs, signal }`:

```ts
const client = new FinixClient({
  environment: "sandbox",
  applicationId,
  formReadyTimeoutMs: 20_000,  // default
  submissionTimeoutMs: 30_000, // default
  script: { timeoutMs: 15_000 }, // default script load timeout
});

await client.mount(host, options, { timeoutMs: 10_000 });
await form.submit({ timeoutMs: 15_000 });
```

A timed-out mount destroys the owned resources and invalidates a late `onLoad`. A timed-out submit rejects with code `timeout`.

## Abort

Pass an `AbortSignal` to cancel; the rejection code is `aborted`. The React hook aborts the mount automatically on unmount.

```ts
const controller = new AbortController();
const pending = client.mount(host, options, { signal: controller.signal });
controller.abort();
```

## Concurrency and lifecycle

- A second `submit()` while one is pending rejects with `submission_in_progress`.
- After `destroy()`, `submit()` rejects with `destroyed`; a pending submission is rejected too.
- `loadFinix()` rejects conflicting script versions with `script_conflict` and retries cleanly after a failed load.

The full list is on [Error codes](/docs/reference/errors).
````
